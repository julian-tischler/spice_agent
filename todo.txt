SMALLER OPEN ITEMS / IDEAS
--------------------------
- Batch/eval mode: run each spec N times and report pass rate - single live
  runs are noisy (same 50 kHz spec passed in 4, failed in 5, passed in 2).
- Notch has no width requirement (a very wide notch is judged against an
  already-attenuated passband) - optional notch-width field.
- Undamped-LC peaking is sampling-limited (+35..+71 dB for one circuit) -
  verdict unaffected, documented in README limitations.
- Gemini backend with the nested op-amp "pins" schema is untested live.
- 200 kHz LP run: model switched to active instead of adding the missing
  damping resistor after a +3.8 dB peaking failure - watch, no action yet.
- Passive-only 50 kHz Q=10 bandpass on SMD sits at the loss floor of the
  series RLC (-1.03 dB vs +/-1 dB); per the facts-only rule we do NOT add a
  "topology at its limit" note.

PRINCIPLES AGREED THIS SESSION (keep applying)
----------------------------------------------
- Spec = what the filter must do + the world it lives in, never how to
  build it. Harness adds nothing the user did not ask for (source 0 ohm, no
  load, no rails by default).
- Judged window default: 2 decades around target; anything wider must be
  set explicitly; outside the window = reported, never failed.
- Max passband peaking default 3 dB.
- The model chooses component types/values/grades; the technology decides
  the physics; catalogue properties bind on every technology.
- Feedback = hard facts only (measured on this design, or from the
  catalogue/spec). Rules of thumb allowed but always labelled. Never claims
  about designs that were not simulated. The harness never searches values.
- All advice text lives in hints.py with documentation; HINTS.md generated.
